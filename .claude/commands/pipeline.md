# 총괄 PM 파이프라인

지금부터 당신(메인 세션)이 총괄 PM입니다. 서브 에이전트는 다른 서브 에이전트를 호출할 수 없으므로, 모든 에이전트 소환은 PM인 당신이 직접 합니다. 아래 [고정 워크플로우]를 순서대로 수행하세요.

요구사항: $ARGUMENTS

## 재시도 정책 (사용자가 따로 바꾸라고 하기 전까지 고정)
- QA 테스트 단계: 실패 시 **최대 1회** 재시도
- CI 빌드 단계: 실패 시 **최대 2회** 재시도
- 코드 리뷰 단계: 불합격 시 **최대 1회** 재시도
- 재시도 = 실패 리포트 전문을 `developer`에게 넘겨 수정시킨 뒤, 같은 단계를 처음부터 다시 실행
- 재시도 횟수를 모두 소진하고도 실패하면 즉시 파이프라인을 중단(Aborted)하고, 마지막 에러 리포트를 가공 없이 개발자에게 출력한 뒤 종료하세요.

## 고정 워크플로우
1. **[코드 구현]** `developer`에게 요구사항을 전달해 CLAUDE.md 컨벤션에 맞게 로컬 소스코드를 작성/수정하게 합니다. 수정 파일 목록을 받아 보관하세요.
2. **[QA 테스트]** `qa-tester`를 소환해 테스트를 검증합니다. 실패 시 재시도 정책(1회)을 적용합니다.
3. **[시니어 리뷰]** 테스트 통과 후 `code-reviewer`를 소환합니다. 결과에 `REVIEW_PASSED`가 없으면 불합격으로 보고 재시도 정책(1회)을 적용합니다. 수정이 일어났다면 재리뷰 전에 2단계(QA)도 다시 통과해야 합니다.
4. **[CI 빌드 검증]** 리뷰 합격 후 `ci-validator`를 소환합니다. 실패 시 재시도 정책(2회)을 적용합니다. 수정이 일어났다면 CI 재실행 전에 QA 단계도 다시 통과해야 합니다.
5. **[노션 기록]** 모두 통과하면 `notion-logger`를 소환합니다. 넘길 내용은 다음 3가지로 제한합니다.
   - 요구사항 요약 (원문 전체가 아니라 핵심만)
   - 수정/생성된 파일 목록
   - QA / 리뷰 / CI 결과 요약 (재시도 횟수 포함)
6. **[최종 보고]** 변경된 아키텍처 구조, 수정 파일 목록, 노션 기록 완료 여부를 개발자용 리포트로 출력하고 마무리하세요.
