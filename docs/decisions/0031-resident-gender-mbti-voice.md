# 0031. 주민 성별·MBTI·장소를 대화와 목소리에 반영한다

- 날짜: 2026-11-14
- 상태: 검토 중 (실제 소리와 대화는 일부만 확인)

## 배경

- 편의점에 있는 주민(ミク)이 "아타시 집에는 컵라면밖에 없다"고 답했다. 프롬프트에 주민의 `location`이 없어 AI가 장소를 지어냈기 때문이다.
- 주민 목소리가 성별과 무관하게 같은 브라우저 음성에 높낮이만 달랐다.
- 시트의 `personality`는 "무뚝뚝/オレ系"처럼 성격과 1인칭이 섞여 있었다.

## 결정

- **장소**: 프롬프트의 현재 상황에 주민의 `location`을 넣는다. 건물이면 "그 안에서 손님을 맞이하는 주민", `거리`면 "거리에서 마주침". 가게 안이면 점원처럼 응대하고, 장소를 바꿔 말하지 않으며, 말이 어색하면 장소에 맞게 해석해 되묻는 규칙을 더했다.
- **MBTI**: 시트의 `personality`를 MBTI 4글자로 바꾸고, 1인칭·말투는 `core_features` 끝의 "말투:" 한 줄로 옮겼다(코드 변경 없음).
- **성별**: 시트에 `gender`(남/여) 열을 더하고 `resident.gender`(`M`/`F`, `V34`)에 저장한다. 프롬프트에 "성별"로 넣고 성별에 맞는 말투를 일관되게 쓰게 한다. 글에서 분명하지 않은 렌은 여, 아키라와 소라는 남으로 정했다.
- **목소리**: 서버 Google 음성을 성별로 고른다(여 `ja-JP-Neural2-B`, 남 `ja-JP-Neural2-C`). 주민별 높낮이·속도를 Google의 `pitch`/`speakingRate`로 연결하고 서버 음성을 못 쓰면 브라우저 음성에 같은 값을 쓴다. 저장 키는 `voice|p…|r…`로 구분한다.
- **높낮이 제한**: 브라우저 음성용으로 정한 값을 그대로 쓰니 +10 반음에서 소리가 끊겼다. 서버에서 ±3 반음으로 제한한다. 주민별 차이는 속도와 남녀 음성으로 낸다.

## 대안

- 브라우저 음성만 유지: 일본어 음성이 하나뿐이라 성별을 바꾸기 어렵다.
- 모델 교체: 끊김의 원인은 모델이 아니라 높낮이 값이었다.

## 한계

- 일본어 Google 음성은 여성 음성이 적어 여성 주민의 구분이 약하다.
- ミク는 아이돌 설정인데 편의점 점원으로 응대한다. 어색하면 시트의 `location`이나 배경을 조정한다.
