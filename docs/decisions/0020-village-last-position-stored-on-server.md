# 0020. 마을 마지막 위치: 서버에 저장하고, 이벤트 때만 보낸다

- 날짜: 2026-11-09
- 상태: 구현함

## 배경

마을에서 마지막으로 서 있던 자리를 기억해 다음에 들어올 때 거기서 시작하고 싶다. 저장 위치는 클라이언트(localStorage)와
서버 두 후보였다.

## 결정

- **서버에 저장한다.** 기기·브라우저를 바꿔도 이어지고, 건물 열림(`0019`)처럼 "내 마을 상태"를 한곳에 모을 수 있다.
  localStorage는 구현이 가장 간단하지만 브라우저마다 따로이고 데이터 삭제로 사라진다.
- **별도 표 `user_village_position`**(`user_id` PK, `x`, `z`, `updated_at`)에 저장한다(`V22`). 처음에는 `users`에 컬럼을
  넣었으나(`V21`), 위치는 자주 바뀌는 값이라 로그인·프로필이 쓰는 `users` 행을 계속 갱신하게 되고(행 버전이 계속 늘고
  `updated_at`이 바뀐다) 위치가 `User`의 책임이 아니다. 그래서 V22가 표를 만들고 V21로 저장된 값을 옮긴 뒤 컬럼을 지운다.
  행이 없으면 저장한 적이 없는 사용자다. 저장은 `users`를 읽지 않고 `INSERT ... ON CONFLICT (user_id) DO UPDATE` 한 번이다.
- `GET /api/village/position`(저장한 적 없으면 `{x: null, z: null}`), `PUT /api/village/position`(204).
  서버는 좌표가 있고 이동 범위(±17) 안인지만 검증한다. 건물·나무와 겹치는지는 프런트가 복원할 때 확인한다.
- **저장 시점**: 30초마다, 탭이 숨겨질 때(`visibilitychange`), 페이지를 닫을 때(`pagehide`), 마을 화면을 떠날 때, 로그아웃
  직전(로그아웃하면 세션이 끊겨 저장할 수 없으므로). 걸을 때마다 보내지 않고, 프런트가 서버에 마지막으로 보낸 값과 같으면
  요청 자체를 보내지 않는다(서버는 비교하지 않는다). 탭 닫기 순간에도 끊기지 않게 `fetch`의 `keepalive`를 쓴다.
  저장 로직은 `TownPage`가 맡고 `VillageScene`은 위치 변화만 알린다.
- 프런트는 마지막 위치를 받아 온 뒤에 마을을 그린다(기본 위치에서 시작했다가 순간이동하지 않게). 조회가 실패하거나
  저장된 자리가 지금은 막혀 있으면 기본 시작 위치에서 시작한다.
- 건물에 자동 입장(문 앞)할 때 문 앞 자리가 저장되므로 돌아오면 문 앞에 선다. 자동 입장은 벽 쪽으로 걸을 때만 발동해서
  돌아오자마자 다시 들어가지 않는다.

## 알려진 한계

- 비정상 종료(브라우저 강제 종료, 네트워크 끊김)에서는 최대 30초치 이동이 사라질 수 있다.
- 서버 검증 범위(±17)는 프런트 `MAP_HALF_SIZE - 1`과 값만 같다. 땅 크기를 바꾸면 `VillagePositionRequest`도 바꾼다.
