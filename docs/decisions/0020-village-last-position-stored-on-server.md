# 0020. 마을 마지막 위치: 서버에 저장하고, 이벤트 때만 보낸다

- 날짜: 2026-11-09
- 상태: 구현함

## 배경

마을에서 마지막으로 서 있던 자리를 기억해 다음에 들어올 때 거기서 시작하고 싶다. 저장 위치는 클라이언트(localStorage)와
서버 두 후보였다.

## 결정

- **서버에 저장한다.** 기기·브라우저를 바꿔도 이어지고, 건물 열림(`0019`)처럼 "내 마을 상태"를 한곳에 모을 수 있다.
  localStorage는 구현이 가장 간단하지만 브라우저마다 따로이고 데이터 삭제로 사라진다.
- `users`에 `village_x`, `village_z`(둘 다 NULL이면 저장한 적 없음, CHECK로 둘이 함께 NULL/값)를 추가한다(`V21`).
  위치는 사용자 한 명에 하나뿐이라 별도 표를 만들지 않았다.
- `GET /api/village/position`(저장한 적 없으면 `{x: null, z: null}`), `PUT /api/village/position`(204).
  서버는 좌표가 있고 이동 범위(±17) 안인지만 검증한다. 건물·나무와 겹치는지는 프런트가 복원할 때 확인한다.
- **저장 시점은 이벤트뿐이다**: 마을 화면을 떠날 때(건물 입장·화면 이동 포함), 탭이 숨겨질 때(`visibilitychange`), 페이지를
  닫을 때(`pagehide`). 걸을 때마다 보내지 않는다. 탭 닫기 순간에도 끊기지 않게 `fetch`의 `keepalive`를 쓴다.
- 프런트는 마지막 위치를 받아 온 뒤에 마을을 그린다(기본 위치에서 시작했다가 순간이동하지 않게). 조회가 실패하거나
  저장된 자리가 지금은 막혀 있으면 기본 시작 위치에서 시작한다.
- 건물에 자동 입장(문 앞)할 때 문 앞 자리가 저장되므로 돌아오면 문 앞에 선다. 자동 입장은 벽 쪽으로 걸을 때만 발동해서
  돌아오자마자 다시 들어가지 않는다.

## 알려진 한계

- 비정상 종료(브라우저 강제 종료, 네트워크 끊김)에서는 마지막 저장 이후의 이동이 사라질 수 있다.
- 로그아웃 직후 화면이 닫히며 보내는 저장은 세션이 없어 실패한다(무시한다).
