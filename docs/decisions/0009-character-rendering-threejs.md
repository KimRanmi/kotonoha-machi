# 0009. 캐릭터·마을 렌더링: Three.js로 통일 (DiceBear 대체)

- 날짜: 2026-10-23
- 상태: 확정

## 배경

`0008-avatar-customization.md`에서 캐릭터 꾸미기(피부색/머리색/헤어스타일/옷/신발 5축)를
구현하면서, 미리보기 렌더러로 DiceBear voxel-art를 "임시 미리보기"로 채택했다. 실제
렌더링 결과를 확인해보니 두 가지 문제가 드러났다.

- 얼굴 표정(눈/입/눈썹)이 우리가 정한 5축과 무관하게 DiceBear가 seed로 랜덤 결정해,
  같은 설정이어도 사용자마다 표정이 제각각이었다.
- 몸통이 작아 옷(10종)·헤어스타일(8종) 차이가 잘 구분되지 않았다.

이 문제를 풀기 위해 두 방향을 검토했다.

1. **마을 오버월드를 Phaser(2D 게임 프레임워크)로 새로 도입**하고, 캐릭터를 몸/헤어/옷/
   신발을 레이어별로 따로 그려 합성하는 방식으로 구현. 건물 내부는 `0001-tech-stack.md`
   결정대로 Three.js를 유지해, 마을(2D)과 건물 내부(3D) 렌더러를 분리한다.
2. **마을과 건물 내부를 전부 기존 Three.js로 통일**하고, 캐릭터를 단순 도형(박스/원기둥
   등)을 조합한 저폴리 3D 모델로 직접 만들어, 5축 값에 따라 파츠의 색상·형태를 바꾼다.

## 결정

**2번(Three.js로 통일)을 선택한다.**

- `0001-tech-stack.md`가 이미 Three.js를 "3D 장면(건물 내부 등) 전담"으로 확정해뒀고,
  마을 오버월드까지 포함해도 새 프레임워크(Phaser)를 추가로 들일 필요가 없다. CLAUDE.md의
  "추가 프레임워크나 라이브러리는 필요성이 확인되기 전까지 도입하지 않는다" 원칙에 더
  맞는다.
- 두 문제(표정 랜덤, 옷 차이 안 보임)의 근본 원인은 Three.js의 한계가 아니라 "우리가
  통제할 수 없는 외부 2D 생성 서비스(DiceBear)에 의존했다"는 점이었다. 파츠(머리/몸/옷/
  신발)를 직접 만드는 저폴리 3D 모델로 바꾸면 표정이 랜덤으로 끼어들 여지가 없고, 파츠별
  형태를 우리가 원하는 만큼 다르게 만들 수 있다.
- 마을과 건물 내부가 같은 렌더러를 쓰면 건물에 들어갈 때 2D→3D 전환 같은 이질감이 없다.

## 적용 범위

- 프로필 화면의 캐릭터 미리보기와 마을 오버월드의 캐릭터 모두 같은 Three.js 저폴리
  모델을 사용한다.
- 백엔드 API(`GET/PATCH /api/users/me/avatar`)와 저장 데이터(5개 enum)는 바꾸지 않는다.
  `0008`에서 정한 "저장 데이터와 렌더러 분리" 원칙은 그대로 유지하고, 렌더러만 DiceBear
  (외부 2D SVG 서비스)에서 Three.js로 직접 만드는 3D 모델로 바뀐다.
- `0008`의 "한계"와 "나중에 재검토할 조건" 항목(voxel-art 임시 미리보기, 3D 전환 시
  재검토)은 이 결정으로 해소된 것으로 본다.

## 확인되지 않은 점 (실제 구현 시 결정 필요)

- 구체적 모델링 방식: 순수 지오메트리 조합(박스/원기둥 등을 코드로 직접 배치)으로 할지,
  외부에서 구한 저폴리 3D 에셋(글TF 등)을 쓸지는 아직 정하지 않았다.
- 프로필 화면에서 정적 이미지 미리보기가 아니라 Three.js 렌더러 인스턴스를 띄워야 하므로,
  기존 `frontend/src/lib/avatarPreview.ts`(DiceBear URL 생성 함수)를 걷어내고 어떤 구조로
  대체할지는 별도로 설계한다.
- 마을 오버월드의 타일맵/이동/건물 충돌 처리 방식은 이번 결정 범위 밖이며 별도로 설계한다.

## 나중에 재검토할 조건

- 저폴리 3D 캐릭터를 실제로 구현해본 뒤, 개발 비용(파츠별 모델링·애니메이션)이 예상보다
  훨씬 크다고 판단되면 재검토한다.
