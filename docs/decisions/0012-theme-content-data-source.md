# 0012. 테마 학습 콘텐츠(한자·단어·표현·예문) 데이터 출처: kanjiapi.dev + Tatoeba, 1회성 임포트

- 날짜: 2026-10-23
- 상태: 확정

## 배경

테마 학습(오늘의 학습)은 한자 → 단어 → 표현 → 예문 → 독해 순서로 진행하는데, 지금까지는
단계 진행 게이트(순서 강제, 완료 처리)만 구현돼 있었고 각 단계의 실제 콘텐츠는 없었다.
요구사항 문서는 "한자·단어·표현의 뜻/읽는 법은 AI가 생성하지 않고 실제 단어 데이터(DB)에서
가져온다"고 확정했지만, 그 데이터를 어디서 가져올지는 "아직 안 정한 것"으로 남겨뒀다
(자체 제작 vs 공개 JLPT 리스트). 콘텐츠를 직접 만들 사전 지식/시간이 없어서, 공개 데이터를
가져다 쓰는 쪽으로 논의했다.

독해(READING) 지문은 요구사항 문서에 "나중에 고려(RAG)"로 이미 범위에서 제외돼 있어서
이번 결정은 한자·단어·표현·예문 네 단계만 다룬다.

## 검토한 선택지

**한자·단어·표현 출처**

1. **kanjiapi.dev** (선택) — 무료, API 키 불필요. `/v1/kanji/{글자}`로 한자의 음독·훈독·뜻·
   JLPT 레벨을, `/v1/words/{글자}`로 그 글자가 들어간 JMdict 단어/구 항목(표기·읽는 법·뜻)을
   준다. 데이터 원본은 EDRDG의 KANJIDIC2 + JMdict(출처 표기 조건부 무료 라이선스). 래퍼
   자체는 MIT 라이선스.
2. **공개 JLPT 데이터셋 파일 다운로드** (예: OpenJLPT, CC BY-SA 4.0) — GitHub에 이미 만들어진
   JSON/CSV를 통째로 받아서 씀. 서버 호출이 전혀 없다는 장점이 있지만, CC BY-SA의
   동일조건변경허락 조건이 더 엄격하고, 한자+단어+표현을 한 출처로 묶기엔 kanjiapi.dev보다
   불편했다.

**예문 출처**

1. **Tatoeba API** (선택) — 무료, 키 불필요. 언어 필터(`from=jpn&to=kor`)로 일본어 예문과
   한국어 번역 쌍을 바로 검색할 수 있다. 라이선스는 CC BY(출처 표기 필요).
2. 이번 범위에서 예문 생략 — 검토했지만, 한자/단어/표현만 실제 데이터로 채우고 예문만
   비워두면 요구사항의 단계 구조(한자→단어→표현→**예문**→독해)가 중간에 끊겨서 제외했다.

## 결정

**kanjiapi.dev(한자/단어/표현) + Tatoeba(예문)를 1회성으로 호출해 받아온 데이터를 Flyway
마이그레이션(`V7__create_theme_content_tables.sql`)의 INSERT문에 그대로 심는다.**

- 두 서비스 모두 실시간 호출형 공개 API이지만, 요구사항이 "DB에서 가져온다"고 명시하고
  있어서 **운영 중에는 외부 API를 전혀 호출하지 않는다.** 한 번 데이터를 받아 SQL에 리터럴로
  박아 넣으면, 그 뒤로는 완전히 우리 Postgres 안에서만 돈다 — API 서버가 나중에 중단되거나
  요금 정책이 바뀌어도 이미 심어둔 데이터는 영향받지 않는다.
- WORD와 EXPRESSION은 둘 다 kanjiapi.dev의 단어 조회 결과로 데이터 모양(표기/읽는 법/뜻/
  레벨)이 완전히 같아서 `theme_vocabulary` 테이블 하나로 묶고 `stage` 컬럼으로만 구분한다.
  KANJI(`theme_kanji`)와 EXAMPLE(`theme_example`)은 모양이 달라서 별도 테이블로 뒀다.

## 데이터 가공에서 내린 세부 판단

- **JLPT 레벨 숫자 체계**: kanjiapi.dev의 `jlpt` 필드가 구 4단계 체계인지 신 N1~N5 체계인지
  문서로는 확인할 수 없어서, 실제 데이터(`jlpt.tsv`)를 직접 열어 확인했다. 레벨 5 목록에
  水·右·左 같은 가장 기초적인 한자가, 레벨 1 목록에 훨씬 복잡한 한자들이 들어 있어 **신
  체계(5=N5 ~ 1=N1)를 그대로 쓰는 것으로 확인**했고, 그 값을 그대로 저장한다.
- **단어·표현의 JLPT 레벨**: kanjiapi.dev는 단어 단위 JLPT 레벨을 제공하지 않는다. 단어를
  이루는 한자들의 레벨 중 가장 어려운(숫자가 작은) 값을 그 단어의 레벨로 썼다 — AI가 지어낸
  값이 아니라 실제 한자 데이터에서 계산한 값이다. 이 방식은 근사치라 체감 난이도와 다를 수
  있다(예: "道順"은 道=N4, 順=N2라 N2로 매겨졌는데, 단어 자체는 그렇게 어렵게 느껴지지
  않을 수 있다).
- **동음이의어 주의**: kanjiapi.dev의 단어 조회는 같은 표기에 여러 JMdict 항목이 묶여 나올 수
  있다. 예를 들어 "注文"은 흔히 쓰는 "주문"(ちゅうもん, 자주 쓰이는 단어 표시 있음) 외에도
  드문 고어 "주해"(ちゅうぶん, 자주 쓰이는 단어 표시 없음) 항목이 같이 나왔다. 데이터를
  넣을 때 자주 쓰이는 단어 표시(`priorities`)가 있는 항목을 수동으로 선택해 걸러냈다.
- **한글 뜻 번역**: kanjiapi.dev/JMdict의 `meanings`는 영어 설명만 준다. 화면은 한국어라
  영어 뜻을 한국어로 옮겨 적었다. 이 작업은 사전에 이미 확정된 뜻을 그대로 번역하는 것이라
  "AI가 뜻을 지어낸다"는 요구사항이 막으려는 것(런타임에 매번 다르게 생성되는 설명)과는
  다르다고 판단했다 — 번역 결과는 DB에 고정 저장되고, 운영 중 AI 호출은 없다.

## 2026-10-23 수정: V7 데이터가 요구사항의 JLPT 레벨 기준을 벗어남

V7에 처음 심은 샘플 단어(水/물, 右/오른쪽, 左/왼쪽, 注文/주문 등)는 전부 N4~N5
수준이었다. 요구사항 문서는 이미 "JLPT N3~N1 수준"(`docs/requirements.md:103`)을 테마
학습의 콘텐츠 레벨 기준으로 정해뒀는데, 콘텐츠를 고를 때 이 기준을 놓쳤다. "카페에서
주문하기"·"길 묻기"처럼 일상 초급 상황을 주제로 한 테마다 보니, 실생활에서 자주 쓰는
단어(물/오른쪽/왼쪽 등)가 자연스럽게 N4~N5라는 점을 충분히 고려하지 못했다.

`V8__replace_theme_content_with_n1_n3_level.sql`로 데이터를 N1~N3 범위로 교체했다(혼잡/
만석/종류/쓰다/달다, 주변/거리/안내/길을 잃다/건너다 등). 이미 적용된 V7 파일 자체는
고치지 않는다 — Flyway가 적용된 마이그레이션의 체크섬을 검증하기 때문에, 파일을 고치면
이미 V7을 적용한 환경에서 검증 오류가 난다.

**한계**: N1~N3 어휘는 "카페에서 주문하기"·"길 묻기" 같은 생활 밀착형 주제와는 다소
동떨어진 느낌을 줄 수 있다(예: 직접적인 "주문하다"보다 "혼잡하다/만석이다"처럼 상황을
묘사하는 단어 위주가 됨). 테마 주제와 레벨 기준이 자연스럽게 맞아떨어지는 주제 선정은
향후 테마를 늘릴 때 다시 고려한다.

## 2026-11-14 추가: 영어 뜻을 한국어로 옮기는 번역 단계

`scripts/import-theme-content`로 테마를 8개 더 늘리면서 "한글 뜻 번역" 단계를 도구에 넣었다.
이전에는 영어 뜻을 사람이 손으로 옮겨 적었는데, 테마 8개 분량은 손으로 하기 어려워서다.

- 어떻게: kanjiapi.dev가 준 영어 뜻 목록을 Gemini에게 한 번에 보내 한국어로 **옮기게만** 한다
  (새 뜻을 추가하거나 빼지 않게 요구). 테마당 호출은 1회다.
- 왜 괜찮다고 보나: 위 "한글 뜻 번역"과 같은 판단이다. 이미 확정된 사전 뜻을 옮기는 것이라
  요구사항이 막으려는 "AI가 뜻을 짓는 것"과 다르고, 결과는 DB에 고정 저장돼 운영 중 AI 호출은
  없다. 후보 표기·예문 검색어를 AI가 고르는 역할은 그대로이고, 읽는 법·레벨은 사전에서만 가져온다.
- 안전장치: 번역 결과는 "번역 초안(검수 필요)"으로 표시하고, 예문 읽는 법(형태소 분석기 자동
  생성)도 "검수 필요"로 표시한다. 이 표시가 남아 있거나 시트에서 사람이 `ok`로 바꾸지 않은
  행은 마이그레이션이 되지 않는다.
- 실제로 겪은 것: 번역은 사전의 영어 뜻 목록을 거의 그대로 옮기는데, 사전 항목에 컴퓨터 용어
  (예: 予約의 "프로그래밍"), 옛 뜻(宿題의 "숙주") 등 이 테마와 어울리지 않는 뜻이 섞여 있어
  사람이 덜어내는 검수가 꼭 필요했다. 반대로 새 뜻을 만들어 넣은 경우는 발견하지 못했다.
- 사용 모델: 무료 한도(`0033`)를 앱 대화와 나눠 쓰지 않도록 도구는 `gemini-3.5-flash-lite`를 쓴다.

## 적용 범위

- `theme_kanji`, `theme_vocabulary`, `theme_example` 테이블과 기존 샘플 테마 2개("카페에서
  주문하기", "길 묻기")의 실제 콘텐츠(한자 3개·단어 3개·표현 2개·예문 2개씩).
- `GET /api/themes/{themeId}/stages/{stage}/content`로 단계별 콘텐츠를 조회할 수 있다.
- 프런트엔드가 이 콘텐츠를 화면에 표시하는 작업과 정답 채점(3회 오답 게이트)은 이번
  범위에 포함하지 않는다 — 요구사항 체크리스트에서 별도 항목이다.

## 나중에 재검토할 조건
- (2026-11-14 갱신) 새 테마 추가는 구글 시트 방식으로 바꿨다(`0036`). 아래 첫 항목의 "반복 가능한 임포트"가 그것이다.

- 새 테마를 추가할 때마다 지금처럼 수동으로 단어를 고르고 API를 호출해 SQL을 작성하는
  방식이 테마 수가 늘어나면 번거로워질 수 있다. 테마가 많아지면 반복 가능한 임포트
  스크립트를 따로 만드는 걸 재검토한다.
- "단어=구성 한자 중 최저 레벨" 근사치가 실제 체감 난이도와 자주 어긋난다면, 더 나은
  단어 단위 레벨 데이터 출처를 다시 찾아본다.
