# 0034. 테마 콘텐츠를 구글 시트에서 검수하고, 시트에는 Apps Script 웹훅으로 쓴다

- 날짜: 2026-11-14
- 상태: 확정 (개발 단계)

## 배경

학습 테마를 2개에서 10개로 늘리면서, 한자·단어·표현·예문을 도구가 만든 초안 JSON에서
SQL 마이그레이션으로 바로 옮기던 방식(`0012`)이 불편했다. 검수할 항목이 많고(테마당 30~40개),
검수를 하는 사람이 JSON 파일을 열어 고치는 일이 번거롭고, 앞으로 다른 사람에게 콘텐츠를
맡기기도 어렵다. 주민·건물은 이미 구글 시트가 원본이다(`0017`, `0023`).

## 결정

1. **원본은 구글 시트**(탭 `themes`, `kanji`, `vocabulary`, `examples`). 각 행에 `review` 열을
   두고 `draft`(검수 전) → `ok`(승인) → `applied`(이미 DB에 반영됨)로 쓴다.
2. **채우기**: `propose --to-sheet`가 후보 조회·번역까지 끝낸 결과를 시트에 `draft` 행으로
   넣는다. 같은 테마를 다시 보내면 그 테마의 `draft` 행만 교체하고, 검수한 행은 건드리지 않는다.
3. **반영**: `import-sheet.mjs`(`npm run import`)가 `ok` 행만 읽어서 한자·단어의 읽는 법과
   JLPT 레벨을 kanjiapi.dev와 **다시 대조**하고, 다르면 SQL을 만들지 않고 멈춘다(의도한 값이면
   `--accept-mismatch`). 통과하면 테마별로 "없으면 만들고 내용은 지우고 다시 넣는" 마이그레이션
   SQL(`V<n>__upsert_theme_….sql`)을 만든다. 번호는 `origin/master`의 번호까지 봐서 충돌을 피한다.
4. **시트에 쓰는 방법은 Apps Script 웹 앱**이다. 시트에 짧은 스크립트(`apps-script/Code.gs`)를
   붙이고 `/exec` 주소로 보내며, 비밀 토큰(스크립트 속성 `SHEET_TOKEN`)이 맞을 때만 쓴다.

## 검토한 선택지(시트에 쓰는 방법)

- **서비스 계정 + `googleapis` 라이브러리**: 가장 정석이지만 구글 클라우드 설정(서비스 계정, 키
  파일, 시트 공유)이 많고 새 npm 라이브러리가 필요하다. 1회성 개발 도구에는 과하다고 봤다.
- **Apps Script 웹 앱(선택)**: 새 라이브러리·키 파일이 없고, 시트에서 한 번 배포하면 된다. 단점은
  주소를 아는 사람이 호출할 수 있다는 것이라 토큰으로 막았다. 토큰이 샌 것 같으면 스크립트 속성
  값만 바꾸고 `.env`를 맞추면 된다.
- **계속 SQL 파일로만 관리**: 가장 단순하지만 테마를 고칠 때마다 개발 작업이 필요하다.

## 한계

- 시트를 고치는 즉시 앱에 반영되지는 않는다. `import`로 SQL을 만들고 커밋·배포해야 한다.
  운영 중 시트를 직접 읽는 방식은 "운영 중에는 외부 API를 호출하지 않는다"(`0012`)와 어긋나서
  택하지 않았다.
- 시트에서 한국어 뜻과 예문 읽는 법은 사람이 정한 값을 믿는다(사전에 한국어가 없어 대조 불가).
- 웹에 게시한 시트 CSV 주소를 아는 사람은 누구나 읽을 수 있으니 공개해도 되는 내용만 쓴다.

## 도구가 쓰는 Gemini 모델

도구는 영어 뜻을 한국어로 옮기는 번역에만 Gemini를 쓴다(`0012` 추가 절). 앱 대화가 쓰는
`gemini-3.6-flash`의 하루 무료 한도(`0033`)를 나눠 쓰지 않도록 도구는 `gemini-3.5-flash-lite`를
쓴다. `gemini-3.5-flash`는 호출이 `gemini-3.6-flash`의 한도로 잡혀 같은 한도를 소진했다.
