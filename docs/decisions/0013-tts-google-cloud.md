# 0013. 일본어 음성(TTS): 백엔드에서 Google Cloud Text-to-Speech(Neural2) 호출 + DB 캐시

- 날짜: 2026-11-04
- 상태: 구현함, 실제 Google 호출은 아직 검증하지 못함(API 키 `.env` 설정 후 확인 필요)

## 배경

테마 학습의 🔊 듣기와 복습 단계의 "分からない" 힌트가 브라우저 내장 음성 합성(`speechSynthesis`)을 썼는데,
억양이 평평하고 문장 끝이 먹히는 등 학습용으로 부족했다. 배포하면 사용자마다 설치된 음성이 달라서 설정으로
해결할 수도 없다. 나중에 마을 주민과 대화할 때도 같은 음성이 필요하다.

## 검토한 선택지

1. **브라우저 내장 음성** — 무료, 설치된 음성에 따라 품질이 다르고 사용자가 바꿀 수 없다.
2. **Google Cloud TTS (Neural2/WaveNet)** (선택) — 글자 수 기준 과금, 같은 문장은 항상 같은 소리, 무료
   할당량 있음(기억 기준 Standard 월 400만, WaveNet·Neural2 월 100만 글자 — 가격 페이지에서 재확인 필요).
3. **Chirp 3 HD** — 더 사람 같지만 단가가 높다(100만 글자당 $30). 데모에서 들어 본 차이가 크지 않았다.
4. **Gemini TTS** — 토큰 과금이라 비용 예측이 어렵고, 호출마다 소리가 달라질 수 있으며 모델이 자주 바뀐다.

## 결정

- 백엔드의 `tts` 패키지가 `GET /api/tts?text=...`로 MP3를 돌려준다. Google 호출은 백엔드에서만 하고 키는
  `backend/.env`(`GOOGLE_TTS_API_KEY`)에만 둔다. 새 라이브러리 없이 Spring `RestClient`로 REST 호출한다.
- 음성은 `ja-JP-Neural2-B`가 기본값이고 `GOOGLE_TTS_VOICE`로 바꾼다. 음성을 바꾸면 이미 저장한 음성은
  쓰이지 않고 새로 합성한다.
- 합성한 MP3는 `tts_audio` 테이블(음성 + 문장 기준 유일)에 저장하고 모든 사용자가 재사용한다. 학습
  콘텐츠는 모두가 같은 문장을 보므로 사실상 콘텐츠당 한 번만 비용이 든다.
- 비용 보호: 새로 합성할 때만 사용자당 하루 200회, 문장 최대 300자로 제한한다(서버 메모리 기준이라 재시작하면
  초기화된다). 횟수는 구글 호출이 성공한 뒤에 세어서, 키가 없거나 호출이 실패해도 줄지 않는다. Google 쪽에서도 예산 알림과 API 할당량 제한을 걸어 둔다(콘솔 설정은 사용자가 직접 한다).
  Cloud TTS는 Google의 "한도(Spend cap)" 기능 지원 서비스 목록에 없어서 한도로는 막을 수 없다.
- 프런트엔드는 서버 음성을 우선 쓰고, 실패하면(키 없음, 횟수 초과, 네트워크 오류) 브라우저 내장 음성으로
  대신한다.

## 한계 / 나중에 볼 것

- 마을 주민 대화는 매번 새 문장이라 저장 재사용이 거의 안 되고 글자 수가 빨리 는다. 대화 기능을 만들 때 사용자별
  제한을 다시 정한다.
- 하루 횟수 제한이 서버 메모리라 서버를 여러 대로 늘리면 맞지 않는다.
- 오래 안 쓴 음성을 지우는 정리 정책은 아직 없다.
- **임의 문장을 합성할 수 있다.** 로그인한 사용자는 학습 콘텐츠에 없는 문장(최대 300자)도 보낼 수 있고, 새 문장마다
  구글 호출과 `tts_audio` 행이 늘어난다. 회원가입에 제한이 없어 계정을 여러 개 만들면 사용자당 하루 200회 제한도
  우회된다(한 계정당 하루 최대 약 6만 자). 마을 주민 대화에서 매번 새 문장을 읽어야 해서 지금은 학습 콘텐츠로
  제한하지 않았다. 구글 콘솔의 예산 알림과 API 할당량 제한이 마지막 안전장치다. 배포 전에 서버 전체 하루 상한이나
  허용 문장 제한을 정한다.
- 같은 문장을 서로 다른 사용자가 정확히 동시에 처음 요청하면 구글을 두 번 부를 수 있다(저장은 한쪽만 성공하고
  나머지는 무시한다).
- 프런트가 받아 온 음성의 Blob 주소는 페이지를 새로 고칠 때까지 해제하지 않는다.
