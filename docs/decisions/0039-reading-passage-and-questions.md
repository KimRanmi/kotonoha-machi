# 0039. 독해를 지문 + 이해 문제로 바꾸고, 문제 없는 학습은 독해를 건너뛴다

- 상태: **검토 중** (사용자와 방향은 정했으나 출처 표기 문구는 콘텐츠 작업(0038)의 결정을 따른다)
- 날짜: 2026-11-16

## 배경
독해가 "지문을 보고 번역 고르기"라 예문 단계와 거의 같았고, 지문이 없는 학습도 있었다. 지문은 일본어
위키백과(CC BY-SA 4.0)에서 가져오므로 출처 표시가 필요하다. 화면의 "테마"는 "오늘의 학습"으로 바꾼다
(코드·DB 이름 `theme`은 그대로).

## 결정
1. **스키마(`V39`)**: `theme_reading_passage`에 `source_title`·`source_url`·`license`·`is_excerpt`를 더하고
   `translation`을 NULL 허용으로 바꿨다. 새 `theme_reading_question`(질문, 보기 4개, 정답 번호 1~4, **정답 해설 `explanation`**, 순서 — 작업 A 요청으로 해설 열을 더함)을 만들었다.
2. **API**: 독해만 `GET /api/themes/{id}/reading`(지문 + 출처 + 문제 목록, 없으면 204)을 따로 둔다. 문제는 기존
   `ThemeQuizItemResponse`와 같은 모양에 해설이 더해진 `ThemeReadingQuestionResponse`를 쓴다(질문=`prompt`, 보기=`options`, 정답 보기=`correctAnswer`). 그러면 프런트의
   정답 비교와 "3번 틀리면 정답 표시" 규칙을 그대로 쓴다. 기존 `/stages/READING/content`는 빈 목록을 돌려준다.
   - 대안: 독해 전용 DTO만 새로 만들기(프런트 문제 화면을 따로 만들어야 해서 더 복잡해 보류).
3. **건너뛰기는 백엔드 `completeStage`에서 처리한다.** 예문 단계를 끝내 독해가 다음 단계가 됐을 때, 이해 문제가 있는
   지문이 없으면 같은 트랜잭션에서 독해도 완료 처리해 복습으로 보낸다(`ThemeServiceTest`로 고정).
   - 이유: 진행 규칙은 서버가 강제하므로 서버가 단계를 정해야 프런트·서버가 어긋나지 않고, 프런트가 호출을 두 번 하는
     방식보다 단순하다. 단점은 옛 지문만 있는 학습 2개는 지우기 전까지 독해가 건너뛰어진다는 것(의도한 동작).
4. 옛 "번역 고르기" 독해는 새 코드에서 지원하지 않는다. 기존 학습 10개는 이번 작업에서 지우지 않는다(다른 세션이 교체).
5. 출처 표시는 지문 아래에 항상 보인다: "출처: 일본어 위키백과 「제목」(주소), 라이선스" + 발췌면 "도입 단락 발췌".
   링크는 새 탭(`rel="noopener noreferrer"`). 문구는 0038 결정이 정해지면 맞춘다.
