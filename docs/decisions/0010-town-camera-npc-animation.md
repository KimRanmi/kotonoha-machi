# 0010. 마을 카메라 구도·주민(NPC) 외형·캐릭터 애니메이션 범위

- 날짜: 2026-10-23
- 상태: 확정

## 배경

요구사항 "마을 화면 + 캐릭터 이동" 절과 `0009-character-rendering-threejs.md`에는 플레이어
캐릭터가 Three.js 저폴리 3D 모델이라는 것까지만 정해져 있었다. 실제로 마을 화면을
구현하려면 그 위에 세 가지가 더 필요했다 — 카메라를 어떤 구도로 둘지, 카페 주인·알바생·
길거리 주민 같은 NPC는 어떻게 생기게 할지, 이동할 때 걷기 동작까지 넣을지. 세 가지 모두
요구사항에 비어 있어서 사용자와 논의해 정했다.

## 결정

### 1. 카메라 구도: 고정 쿼터뷰(회전 없음)

**검토한 대안**: 캐릭터 등 뒤를 따라다니며 이동 방향에 맞춰 같이 회전하는 3인칭 추적
카메라(GTA, 젤다 스타일). 입체감은 더 크지만, 2D 배경을 "항상 카메라를 향하는" 형태로
그려야 하고, 캐릭터가 도는 방향마다 가림 순서(depth sorting) 계산을 다시 해야 해서
구현 비용이 크다. 채택하지 않는다.

**채택**: 캐릭터가 바라보는 방향이 바뀌어도 카메라 각도는 항상 같게, 위에서 내려다보는
고정 구도다(애니멀 크로싱 느낌의 쿼터뷰). 배경을 한 방향으로만 그리면 되고,
`0001-tech-stack.md`/`0009`가 정한 "배경 2D + 캐릭터 3D 혼합" 방식과 더 단순하게
맞물린다.

### 2. 주민(NPC) 외형: 플레이어와 같은 Three.js 모델 재사용

**검토한 대안**: NPC를 더 단순한 도형이나 2D 스프라이트로 따로 만들기. 개발 비용은
줄지만, 모델링 시스템을 두 개(플레이어용/NPC용) 유지해야 하고 디자인 일관성이
떨어진다. 채택하지 않는다.

**채택**: 카페 주인·알바생, 길거리 주민 모두 플레이어와 동일한 Three.js 저폴리 모델
시스템(`0009`)을 재사용한다. 다만 NPC는 사용자가 꾸미는 대상이 아니므로, 피부색/
머리색/헤어스타일/옷/신발 5축 값은 주민마다 미리 정한 고정값을 쓴다(선택 UI를 거치지
않음).

### 3. 캐릭터 애니메이션 범위: MVP는 걷기 애니메이션 제외

**검토한 대안**: 팔다리가 움직이는 걷기 애니메이션을 MVP에 포함. 완성도는 높아지지만,
마을 화면 하나에 이미 구현 비용이 큰 항목(저폴리 모델링, 카메라, 맵 구역 분리, 건물
아이콘 입장, 가림 순서 계산, NPC 배치)이 몰려 있어 우선순위가 낮다고 판단했다.
채택하지 않는다(지금은).

**채택**: MVP에서는 이동 중 팔다리를 움직이지 않는다. 캐릭터는 이동 방향에 맞춰 몸
전체의 방향(회전)만 바꾸고, 바닥 위에서 위치만 이동한다. 핵심 루프(학습→해금→대화)에
필수가 아니므로 체감 품질 개선 과제로 MVP 이후로 미룬다.

## 적용 범위

- `docs/requirements.md`의 "마을 화면 + 캐릭터 이동" 절에 이 세 결정을 반영한다.
- NPC별 고정 5축 값은 실제 구현 단계에서 주민 데이터(엔티티 또는 시드 데이터)에 함께
  포함한다.

## 나중에 재검토할 조건

- 걷기 애니메이션 없이 이동하는 캐릭터가 실제로 어색하다는 피드백이 나오면 우선순위를
  올려 추가한다.
