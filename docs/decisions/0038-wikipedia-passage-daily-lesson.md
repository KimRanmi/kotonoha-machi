# 0038. 일본어 위키백과 도입 단락을 지문으로 쓰는 "오늘의 학습" 콘텐츠 도구

- 날짜: 2026-11-16
- 상태: 방식 승인됨(2026-11-16, User-Agent는 연락처 없이). 1단계 구현 중이며 점수 기준은 샘플 확인 전

## 배경

학습을 '주제 묶음'(테마)으로 만들어 왔지만, 원하는 것은 하루 하나의 "오늘의 학습"이다.
독해 지문을 주제에 맞게 구하기 어려웠던 문제도 이 방식으로 풀린다: 일본어 위키백과 문서의
도입 단락을 지문으로 고르고, 거기서 한자·단어·표현을 뽑고 예문과 이해 문제를 붙인다.
학습 하나의 이름은 문서 제목이다. 기존 5단계 구조와 DB 이름(`theme`)은 그대로 두고, 콘텐츠를
만드는 입구(`scripts/import-theme-content`)와 독해만 바꾼다. 앱 쪽(화면·스키마)은 별도 세션이 맡는다.

## 지문 출처와 라이선스 (법률 판단이 아니라 공식 안내 요약)

- 일본어 위키백과 본문은 **CC BY-SA 4.0**(2009-06-15 이전 판은 GFDL 병행)이다.
- 근거: [ウィキペディアの文章を二次利用する](https://ja.wikipedia.org/wiki/Wikipedia:ウィキペディアを二次利用する)(ja),
  [Wikimedia Terms of Use §7](https://foundation.wikimedia.org/wiki/Policy:Terms_of_Use),
  [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/deed.ja).
- 재사용 시 필요한 것(위 문서 기준):
  1. **출처 표시**: 문서 링크(URL), 안정판 링크, 저자 목록 중 하나. 각 문서에는 편집 이력 페이지가 있어 저자가 거기 나온다.
  2. **라이선스 표시**: 라이선스 이름과 링크(CC BY-SA 4.0).
  3. **변경 사실 표시**: 일부만 발췌하거나 고쳤으면 그 사실을 밝힌다(도입 단락만 발췌 → "발췌").
  4. **동일 조건 승계**: 개작해 만든 파생물(번역, 지문을 바탕으로 만든 이해 문제 등)은 CC BY-SA 4.0 또는 이후 판으로 공개해야 한다.
  5. 원 문서에 붙은 안내문·배너는 유지한다.
- 이 프로젝트에 대한 의미: 지문 본문과 그 번역·이해 문제는 CC BY-SA 4.0 조건을 따른다.
  **승인 목록(지문 원문)을 저장소에 커밋하면 BY-SA 본문이 저장소에 들어간다**(공개 저장소면 재배포).
  → 출처·라이선스를 파일에 같이 적는다. 단어·한자·예문(Tatoeba CC BY 2.0 FR)과 사전 데이터는 각자 출처가 다르다.
- 확인 못 한 것: 한자·단어 항목처럼 "지문에서 뽑은 낱말"이 파생물 범위에 드는지, 앱 전체의
  라이선스에 영향이 있는지는 판단하지 않았다. 공개 배포 전에 별도로 확인이 필요하다.
- 제외한 후보: Livedoor News Corpus는 CC BY-ND(개작 금지), 위키뉴스는 CC BY 2.5로 달라 폐쇄된 것으로 보여 제외.

## 출처 표기 문구 초안 (화면용, 지문 아래)

> 출처: 일본어 위키백과 「{문서 제목}」([문서 이력]({이력 링크}))
> 리비전 {oldid}, 도입 단락 발췌 / 라이선스: [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/deed.ja)

- 문서 링크는 리비전 고정 링크(`https://ja.wikipedia.org/w/index.php?title=…&oldid=…`), 이력 링크는
  `…&action=history`.
- 한국어 번역·이해 문제 부분에는 "위 지문을 바탕으로 만든 파생물이며 CC BY-SA 4.0으로 제공"이라는 한 줄을 덧붙인다.
- 저장 항목: `source_title`(문서 제목), `source_url`(oldid 링크), `license`("CC BY-SA 4.0"), `is_excerpt`(true). 이력 링크는
  `source_url`에서 만들어 낸다(별도 열 없음). 문구는 화면 쪽 세션과 맞춘다.

## 가져오는 방식

- **공식 MediaWiki API**(`https://ja.wikipedia.org/w/api.php`)를 쓴다. 직접 확인한 결과 동작한다.
  - 본문: `action=query&prop=extracts|revisions&exintro=1&explaintext=1&rvprop=ids&redirects=1`
    (도입 단락 평문 + 현재 리비전 번호 `revid` → `oldid`로 저장).
  - 후보 수집: 날짜 문서(예 「11月16日」)의 섹션 목록(`action=parse&prop=sections`)에서 「記念日・年中行事」
    섹션을 찾고 그 섹션의 링크(`action=parse&section=N&prop=links`)를 모은다.
    직접 시험해 보니 연도(「1995年」)·지명·신문사 같은 링크가 섞여 있어, 문서 제목 필터(연도·`年`/`月`/`日`로 끝나는 제목,
    존재하지 않는 문서 제외)와 길이·점수 거름으로 걸러야 한다.
  - 보조: 「秀逸な記事」·「良質な記事」 분류(`Category:秀逸な記事`는 `list=categorymembers`로 접근 가능함을 확인). 후보가 부족할 때만 쓴다.
- **API 규칙**(MediaWiki API Etiquette, Wikimedia User-Agent Policy): 요청은 하나씩 순서대로, 제목을 `|`로 묶어 배치,
  `maxlag` 사용, 조회 간격 조절, 결과는 캐시해 같은 문서를 다시 부르지 않는다.
  **User-Agent는 필수**이고 "식별 가능한 이름 + 연락처"를 권장하며 브라우저 UA 흉내는 금지, 일반적인 UA는 403이 날 수 있다.
  → 기본은 `kotonoha-import-tool/0.1`. 연락처(메일·사이트)를 넣을지는 **사용자에게 묻는다**(아래 질문). 이메일을 임의로 넣지 않는다.
