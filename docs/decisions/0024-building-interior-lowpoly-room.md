# 0024. 건물 내부: 걸어다니는 저폴리 3D 방, 가구 배치는 프런트 데이터 파일

- 날짜: 2026-11-10
- 상태: 확정 (가구 배치를 구글 시트로 옮길지는 아직 정하지 않음, 아래 "남은 문제")

## 배경

건물에 입장하면 내부 화면 없이 바로 대화 화면(`/chat/{주민 slug}`)으로 갔고, 주민이 없는 집은 들어갈 수 없었다.
요구사항은 "내부 배경은 2D, 캐릭터만 3D"였지만 마을은 이미 건물·나무까지 모두 저폴리 3D로 그리고 있다.

## 결정

- **화면 형태**: 새 화면 `/town/buildings/{건물 id}`. 건물 특성에 맞는 가구가 놓인 방 안을 내 캐릭터가 걸어다닌다.
  안에 서 있는 주민(건물 API의 `residentSlug` 한 명)에게 다가가면 대화 버튼이 뜨고, 현관 매트에 서면 나가기 버튼(Enter)이 뜬다.
  집을 포함한 모든 건물에 들어갈 수 있다.
- **그리는 방식**: 마을과 같은 저폴리 3D. 가구는 상자·원기둥·공 부품을 조합해 만든다. 카메라는 마을과 같은 고정 쿼터뷰이고,
  방 전체가 한 화면에 들어오므로 캐릭터를 따라가지 않는다. 벽은 카메라 반대편 두 면(뒤·왼쪽)만 세운다.
- **가구 배치 데이터**: 프런트 `lib/buildingInteriors.ts`에 건물 id별로 바닥·벽 색, 주민 자리, 가구 목록(종류·좌표·90도 단위 방향·색)을 둔다.
  가구 모양은 `lib/buildingInterior3d.ts`가 종류별로 만든다. 방 크기는 모든 건물이 같다(10 × 8).
  목록에 없는 건물(시트에 새로 추가한 건물)은 창문과 화분만 있는 기본 방으로 그린다.

## 검토한 선택지

- **구경만 하는 고정 방 + 버튼**: 구현은 작지만 마을의 "걸어다니는" 경험이 건물 안에서 끊겨서 제외.
- **대화 화면 배경만 꾸미기**: 가장 작지만 주민이 없는 집은 여전히 들어갈 수 없어서 제외.
- **2D 그림 배경 + 3D 캐릭터**: 요구사항의 처음 문구대로지만, 가구 뒤로 캐릭터가 가려지는 순서를 따로 계산해야 하고 마을과 그림 방식이 달라져서 제외.
- **가구 배치를 구글 시트 → DB → API로**: 코드 수정 없이 배치를 바꿀 수 있지만 import 스크립트·테이블·API까지 필요해 이번 작업에 비해 크다.
  나중에 옮기기 쉽도록 배치를 "값 목록"으로만 적었다(가구 모양 자체는 어느 쪽이든 코드다).

## 남은 문제

- 가구 배치를 구글 시트로 옮길지.
- 건물 안 주민은 한 명만 서 있다. 같은 건물 주민 여러 명 배치와 대화 상대 고르기는 따로 정한다.
- 건물 안에 서 있는 주민이 마을 풀밭에도 그대로 서 있다(주민의 지금 위치 개념이 아직 없다).
- 대화 화면의 "← 마을로"는 건물 안이 아니라 마을로 돌아간다.
