# ことばのまち 요구사항 정의

> 일본어를 공부하고, 내가 살고 싶은 작은 일본 마을을 만들어가는 게임이다.
> 그 마을에서 내 캐릭터로 직접 생활하고, 주민들과 실제 일본어로 이야기한다.

요구사항은 처음부터 다시 정하는 중이다. 확정된 내용부터 이 문서에 쌓아간다. 이전에
만들었던 코드와 기획은 git 기록에 그대로 남아있어서, 필요하면 언제든 참고할 수 있다.

---

## MVP 범위

| 기능 | 포함 여부 | 비고 |
|---|---|---|
| 로그인 / 회원가입 | ✅ 포함 | 이메일+비밀번호, 이메일 인증, 소셜 로그인 |
| 프로필 (닉네임 수정 + 캐릭터 꾸미기) | ✅ 포함 | |
| 테마 학습 (오늘의 학습) | ✅ 포함 | 1순위 기능 |
| 주민과의 대화 (채팅) | ✅ 포함 | 2순위 기능, 타이핑+음성, 발음 체크 |
| 일본어 입력 도우미 | ✅ 포함 | 로마자 자동 변환 + 화면 가상 키보드 |
| 학습 단어장 | ✅ 포함 | |
| 주민 음성 (TTS) | ✅ 포함 | 브라우저 TTS, 주민마다 다른 목소리 (결제 없이) |
| 마을 화면 + 캐릭터 이동 | ✅ 포함 (구조상 필수) | 자유 이동, 구역 나눠 연결, 건물은 아이콘 클릭 입장, 배경 2D + 캐릭터만 3D |
| 테마 완료 → 마을에 건물 해금 반영 | ✅ 포함 (핵심 루프에 필수) | 건물은 정해진 자리에 자동 생성, 집은 직접 배치 |
| 마을/집 꾸미기 | ⏳ 나중 | 3순위 기능, MVP 이후로 미룸 — 테마 학습·주민 대화(1·2순위)부터 먼저 |
| 앱(모바일) 배포 | ⏳ 나중 | PWA 또는 Capacitor로 추후 고려 |

## 확정된 요구사항

### 핵심 루프

**확정 사항:**

```
일본어 학습(테마) → 건물·아이템 해금 → 마을에 반영 → 주민과 일본어로 대화
      ↑                                                    │
      └── 대화 중 모르는 단어를 학습 목록에 추가 ←──────────┘
```

- 학습→마을 성장 연결 단위는 "테마/레슨"이다.
- 학습하는 날: 테마 완료 → 새 한자·단어 습득 → 건물·꾸미기 아이템 해금. 꾸미기 아이템은
  학습으로 얻는다.
- 학습하지 않는 날에도 주민 방문·대화로 관계(친밀도)가 쌓인다.
- 친밀도는 방문/대화 빈도로 오르고, 친밀도 보상은 새 대화 주제/에피소드다(꾸미기 재화가
  아님).
- 대화 중 모르는 단어를 학습 목록에 추가하면, 다시 학습으로 연결된다.
- 관계가 깊어지면 주민의 말투와 화제가 자연스럽게 달라진다.

로그인 후 우선순위는 다음 순서다.

1. 오늘의 새 단어·문법 배우기
2. 주민과 대화하기 (회화 능력 향상 목적)
3. 마을/집 꾸미기

- 하루에 진행할 수 있는 테마 개수는 제한하지 않는다. 다만 Gemini API 호출 비용은 별도로
  모니터링한다.
- 주민과의 대화량(하루 메시지 수)도 제한하지 않는다.
- 서비스는 완전 무료로 간다. MVP는 게임 콘텐츠를 증명하는 데 집중하고, 수익화는 출시 이후
  별도로 검토한다.

**미정:** 테마의 구체적 크기, 학습을 오래 안 했을 때 마을에 부정적 신호(퇴색 등)를 줄지.

### 로그인 / 회원가입

**확정 사항:**
- 이메일 + 비밀번호로 가입한다.
- 가입 시 이메일로 숫자 인증 코드를 보내고, 그 코드로 확인해야 가입이 완료된다.
- 가입할 때 **닉네임**도 함께 받는다 — 마을 주민들이 나를 부를 때 쓰는 이름이다. 다른
  사람과 중복되지 않아야 하며, 가입 중에 중복 여부를 확인할 수 있어야 한다.
- 로그인하지 않으면 다른 화면에 접근할 수 없다(로그인 필수).
- 이메일/비밀번호 외에 소셜 로그인도 지원한다. 구글·카카오·네이버 세 곳을 지원한다
  (`SocialProvider`에 이미 구현됨).
- **로그아웃**: 세션을 즉시 무효화한다.
- **비밀번호 재설정(분실 비밀번호)**: 가입 때와 같은 이메일 인증 코드 방식으로 본인 확인
  후 새 비밀번호를 설정할 수 있다. MVP 범위에 포함한다.
- **이메일 인증 코드 보안**: 코드 유효시간은 10분, 코드 확인 실패는 5회까지 허용하고
  초과하면 거부한다(둘 다 이미 구현됨, `AuthService`). 재발송(resend) 요청에는 60초
  쿨다운을 둬서 짧은 시간 안에 연속 재발송하는 것을 막는다(현재는 쿨다운이 없어 추가
  필요).
- **회원 탈퇴**: 소프트 삭제로 처리한다(`UserStatus.WITHDRAWN`, 행은 보존하고 상태만
  변경). 탈퇴 즉시 로그인이 막히고 세션도 무효화된다. 비밀번호가 있는 계정은 현재 비밀번호
  재확인 후 탈퇴, 소셜 전용 계정은 재확인 없이 탈퇴한다. 자세한 이유와 한계는
  [`docs/decisions/0006-account-deletion.md`](docs/decisions/0006-account-deletion.md)
  참고.

### 프로필 (닉네임 수정 + 캐릭터 꾸미기)

**확정 사항:** 닉네임을 나중에 수정할 수 있고, 내 캐릭터 꾸미기도 같은 화면에서 할 수
있어야 한다. 가입 때와 마찬가지로 닉네임은 중복 확인이 필요하다. MVP 범위에 포함한다.
꾸미기 항목은 최소 **피부색 / 머리색 / 헤어스타일 / 옷 / 신발** 다섯 가지 축으로 고른다(와이어프레임 기준).
**비밀번호 변경**도 이 화면에서 할 수 있다(비밀번호가 있는 계정 기준). MVP 범위에 포함한다.

**미정:** 각 축의 구체적인 선택 개수·색상·스타일 값은 아직 정하지 않았다 — 실제 캐릭터
에셋을 만드는 단계에서 정한다.

**검토했지만 포함 안 함:** 이메일 입력 시 도메인을 드롭다운으로 고르는 방식(예: 아이디
+ naver.com/gmail.com 선택) — 최근 트렌드와 맞지 않아 제외하고, 단일 입력 칸으로 간다.
출석체크(캘린더로 로그인한 날짜 보기)도 비용은 낮지만 지금 범위에서는 제외하고, 필요하면
나중에 추가한다.

### 테마 학습 (오늘의 학습)

**확정 사항:**
- JLPT N3~N1 수준, 한 테마는 한자 → 단어 → 표현 → 예문 → **독해** 순서로 진행한다(한
  단계를 끝내야 다음으로 간다). 독해는 짧은 지문을 읽고 이해하는 라운드다.
  한자·단어·표현의 뜻/읽는 법은 AI가 생성하지 않고 실제 단어 데이터(DB)에서 가져온다.

**나중에 고려 (RAG):** 독해 지문은 AI가 매번 자유롭게 지어내면 난이도나 일본어 품질이
불안정할 수 있다. 실제 검증된 JLPT 독해 지문 모음(코퍼스)을 구해서 레벨·테마에 맞는
지문을 검색(RAG)해 오고, AI는 그 지문을 바탕으로 이해 문제만 만들게 하는 방식을 나중에
고려한다. 지금은 참고용 지문 자료가 없어서 MVP에는 포함하지 않는다.
- 검색(벡터 DB)은 새 DB를 따로 두지 않고, 이미 쓰는 PostgreSQL에 **pgvector 확장**을
  추가해서 처리한다.
- 검색된 지문을 바탕으로 이해 문제를 만드는 LLM은 **새로 추가하지 않고, 이미 쓰는
  Gemini API를 그대로 재사용**한다 — 검색된 지문을 프롬프트에 끼워 넣고 "이 지문으로
  문제를 만들어줘"라고 시키는 방식이라, 벡터 검색(pgvector)만 새로 추가되는 부분이다.
- 학습 중인 단어·표현마다 **지금 몇 레벨(N3~N1)인지 화면 위에 표시**한다.
- 정답을 맞혀야 진행하는 정확도 게이트다. 3회 틀리면 힌트/정답을 보여준다.
- 모든 라운드가 끝나면, 배운 표현으로 직접 답해보는 종합 복습이 있다.
- 학습 진행 상황(완료한 테마 등)은 서버에 저장된다.
- **테마 진행 순서**: 고정된 순서를 강제하지 않고 자유 선택이다. 사용자가 원하는 테마로
  언제든 건너뛸 수 있다.
- **3회 오답 후에도 또 틀리면**: 힌트/정답을 보여준 뒤에도 계속 틀릴 수 있고, 맞힐 때까지
  무제한으로 재시도할 수 있다(강제로 다음 단계로 넘기지 않는다).
- **발음 체크**: 단어·예문을 음성으로 따라 읽으면, 말한 내용을 텍스트로 바꿔서 맞는
  문장인지 확인한다. 음소 단위의 정밀한 발음 채점은 아니다(기술적으로 일본어 지원이
  아직 불안정해서 MVP 범위에서는 제외).

### 주민과의 대화 (채팅)

**확정 사항:**
- 입력은 타이핑과 음성 둘 다 지원한다(둘 중 하나를 고르는 게 아니라 같이 제공한다).
- 음성으로 말했을 때도 테마 학습과 같은 방식의 발음 체크를 적용한다.
- 사용자의 일본어에 오류가 있을 때 AI가 대충 넘기지 않고 적절히 처리해야 한다. 지금까지는
  "어색해도 알아듣고 올바른 표현을 자연스럽게 되풀이해달라"는 지침만 있었는데, 실제로는
  잘 안 지켜지고 그냥 넘어가는 경우가 많았다. 구체적으로 어떻게 고칠지(프롬프트 강화,
  별도 검증 단계 추가 등)는 구현 단계에서 정한다.
- **대화 구조**: 주제를 미리 정해두지 않고 완전 자유 대화다. 주민과 사용자가 무슨 말이든
  주고받을 수 있다.
- **친밀도 표시**: 친밀도(관계) 수치를 화면에서 사용자가 직접 볼 수 있게 표시한다.
- **대화 기록**: 주민과의 대화 내용을 서버에 저장하고, 나중에 다시 볼 수 있다.

### 일본어 입력 도우미

**확정 사항:** 일본어 자판이 없는 한국 사용자를 위해, 일본어를 직접 입력하는 모든 곳
(주민과의 대화, 테마 학습의 답변 입력 등)에 아래 두 가지를 **같이** 제공한다(하나만
고르는 게 아님).
- **로마자 자동 변환**: 영문 키보드로 로마자를 치면 자동으로 히라가나로 바뀐다.
  `wanakana` 라이브러리로 처리한다. 가타카나가 필요한 경우를 위해 히라가나/가타카나
  전환 토글도 함께 제공한다(자동 판별이 아니라 사용자가 직접 전환).
- **화면에 보이는 가상 키보드**: 클릭/터치로 글자를 입력할 수 있는 일본어 가상
  키보드도 화면에 띄운다.

### 마을 화면 + 캐릭터 이동

**확정 사항:**
- 이동 방식은 방향키/WASD로 자유롭게 걸어다니는 방식이다.
- 맵은 하나의 맵에 다 몰아넣지 않고, 구역을 나눠서 서로 연결한다(이동하면 로딩되는
  방식).
- 건물 입장은 걸어서 다가가 힌트를 보고 들어가는 방식이 아니라, 맵 위 건물 아이콘을
  클릭하면 걷는 과정 없이 바로 들어간다.
- 마을·건물 내부의 배경은 2D로 그리고, **캐릭터만 3D(Three.js)로 렌더링**한다(배경 2D +
  캐릭터 3D 혼합). 프로필에서 고른 꾸미기(피부색·머리색 등)가 입체감 있게 반영된다.

**알려진 과제:** 2D 배경과 3D 캐릭터를 섞으면, 캐릭터가 배경의 어떤 요소 앞/뒤에 있는지
(가림 순서)를 직접 계산해서 맞춰줘야 한다. 전부 2D거나 전부 3D면 자동으로 되는 부분이라,
구현 단계에서 신경 써야 할 지점으로 남겨둔다.

**MVP 범위:**
- 처음에는 건물 1개(카페)만 있지만, 그 안에는 주민이 **여러 명**(예: 카페 주인 미유 +
  알바생 나나, 2명) 있다.
- 건물에 들어가지 않아도, **마을 길거리를 돌아다니는 주민**이 있어서 걷다가 마주치면
  바로 대화를 걸 수 있다. 전부 건물 안에서만 만나는 게 아니라 "진짜 돌아다니는 마을"
  느낌을 준다.
- **주민 상호작용 방식**: 길거리 주민에게 가까이 다가가면 말풍선/버튼이 나타나고,
  사용자가 그것을 눌러야 대화가 시작된다(다가가는 즉시 자동으로 시작되지 않는다).
- **구역(존) 구성**: 처음부터 여러 구역으로 나누지 않고, 작게 시작한다(중앙 광장 +
  카페 주변 1구역). 건물이 늘어나면 구역도 함께 늘린다.
- **UI 언어**: 게임 UI(버튼, 메뉴 등)는 한국어로 고정한다. 다국어 지원은 MVP 범위에
  넣지 않는다.
- **온보딩**: 처음 가입한 사용자에게 마을 이동, 주민과의 대화, 테마 학습 조작법을
  설명하는 튜토리얼 화면이 필요하다.

### 테마 완료 → 마을에 건물 해금

**확정 사항:**
- 테마 완료로 해금되는 건물(카페, 상점, 마을회관 등)은 사용자가 위치를 고르지 않고
  **정해진 자리에 자동으로 생긴다**.
- 단, **내 집(home)은 예외**다 — 사용자가 원하는 위치에 직접 배치할 수 있다.
- 건물마다 담당 주민이 1명 고정으로 연결된다.
- **MVP에서 해금 가능한 건물**: 카페, 상점, 마을회관, 집(4개)으로 시작한다.
- **집 내부**: 다른 건물과 마찬가지로 아이콘을 클릭하면 내부(배경 2D + 캐릭터 3D) 화면으로
  들어갈 수 있게 구현한다(외형만 있고 들어갈 수 없는 상태로 두지 않는다).
- **해금 피드백**: 건물이 새로 생길 때 토스트나 짧은 애니메이션으로 사용자에게 알린다.

### 학습 단어장

**확정 사항:** 대화 중 저장한 단어는 뜻·읽는 법이 함께 보여야 한다. 대화 중 저장한
단어뿐 아니라, **테마 학습 중 배운 단어도 자동으로 단어장에 들어간다**.

**배경:** 지금까지는 단어만 저장되고 뜻/읽는 법 같은 설명이 전혀 없어서, 저장해봐도
학습에 쓸모가 없었다.

### 주민 음성 (TTS)

**확정 사항:** 주민마다 목소리가 서로 다르고, 자연스러운 음질이어야 한다.

**배경:** 지금까지는 브라우저에 내장된 기본 음성 합성(Web Speech API)을 그대로 썼다.
주민 구분 없이 전부 같은 기계적인 목소리로 나와서 자연스럽지 않았다.

**구현 방식 확정:** 브라우저에 내장된 음성 합성(Web Speech API)을 그대로 쓰되, 주민마다
다른 목소리를 배정한다. 결제가 필요한 외부 TTS 서비스(Google Cloud TTS 등)는 쓰지 않는다.
재생 컨트롤은 **다시 듣기 버튼만** 제공한다(속도 조절 등은 MVP 범위에 넣지 않는다).

**검토했지만 채택 안 함:** Google Cloud Text-to-Speech(Gemini-TTS) — 일본어 지원과
목소리 다양성(약 30개)은 좋지만, 지금 쓰는 Gemini API와는 별개 상품이라 결제 연결이
필요하고, 아직 preview 단계라 안정성도 불확실하다. 결제 없이 가고 싶다는 결정에 따라
제외한다.

**한계:** 브라우저/OS에 설치된 목소리 범위 안에서만 선택할 수 있어서, "자연스러움"은
제한적으로만 개선된다.

## 아직 안 정한 것

- **테마 학습 독해(READING) 지문 출처**: 한자·단어·표현·예문 출처는
  `docs/decisions/0012-theme-content-data-source.md`에서 정했지만, 독해 지문은 여전히
  미정이다(요구사항 "테마 학습" 절의 "나중에 고려(RAG)" 항목).
- **학습 단어장 UI 상세**: 검색/필터(레벨별 등), 복습(퀴즈 모드) 기능 여부.
- **마을 길거리 주민의 이동 패턴 상세**: 랜덤으로 돌아다니는지, 정해진 경로를 순환하는지.
- **마을 시간/날씨 시스템**: 낮/밤, 계절 등 분위기 변화를 넣을지 여부 — 아직 고려 안 함.
- **TTS의 OS/브라우저별 보이스 차이 대응**: 일본어 보이스가 설치되지 않은 환경의
  폴백 처리.
- **모바일 브라우저 반응형**: 방향키/WASD 이동을 터치로 어떻게 대체할지(앱 배포 자체는
  "나중"이지만, 모바일 브라우저 접근은 당장도 있을 수 있음).
- **Gemini API 응답 실패/지연 시 사용자 경험**: 재시도 버튼, 로딩 표시 등 에러 처리 방식.
- **소셜 계정 연동/해제**: 이메일 가입 계정에 소셜 계정을 나중에 추가로 연동하거나 해제할
  수 있는 화면이 필요한지.
